# Context filters and the tool-output shrinker

## Request path

A turn starts in `run_turn`. After step context is captured, the session freezes reasoning-retention verdicts and builds the first prompt input:

1. `run_turn` calls `Session::freeze_reasoning_retention` at `core/src/session/turn.rs:374`.
2. It calls `Session::prompt_input_for_step` at `core/src/session/turn.rs:378`.
3. `prompt_input_for_step` clones history and calls `ContextManager::for_prompt_measured` with the current turn ID (`step_context.turn.sub_id`) at `core/src/session/mod.rs:4055-4063`.
4. `run_sampling_request` reuses that first input. On a sampling retry, it calls `prompt_input_for_step` again at `core/src/session/turn.rs:1393-1398`, then `build_prompt` at `core/src/session/turn.rs:1403-1408`. `build_prompt` adds tools, base instructions, and output-schema information; it does not filter history.

The actual request-time history pipeline is `ContextManager::for_prompt_annotated` at `core/src/context_manager/history.rs:315-341`. It runs, in order:

1. drop completed turn-scoped items (`history.rs:321`);
2. normalize history (`history.rs:322`);
3. shrink completed tool outputs (`history.rs:324-330`).

The remaining sections list those filters and their gates. Function/custom tool-output truncation is a different mechanism and is covered separately at the end.

## Turn-scoped drops

`drop_completed_turn_scoped_items` retains or removes an envelope according to `dropped_reason`, implemented at `core/src/context_manager/history.rs:348-387` and `core/src/context_manager/history.rs:714-739`.

An invisible item is dropped when:

```rust
invisible_owner.is_some()
    && !belongs_to_active_turn(active_turn_id, invisible_owner)
```

That gate is at `history.rs:719-722`. Invisible ownership is assigned when the item is recorded at `core/src/session/mod.rs:3238-3241`.

A reasoning item is dropped when it does not belong to the active turn and its frozen retention verdict is not `Some(true)`:

```rust
!matches!(envelope.item, ResponseItem::Reasoning { .. }) -> keep
belongs_to_active_turn(active_turn_id, reasoning_turn) -> keep
metadata.reasoning_retained != Some(true) -> drop
```

Those checks are at `history.rs:723-738`. Reasoning ownership is assigned when the item is recorded at `core/src/session/mod.rs:3242-3243`. `belongs_to_active_turn` is true only when both IDs are present and equal (`history.rs:765-769`).

The first dropped envelope fixes `report.prefix_break` to that original history index with `get_or_insert` at `history.rs:358-361`. If nothing is dropped, `prefix_break` remains `None`.

These drops can only take effect at a turn boundary in ordinary operation. The active turn ID is constant across prompt retries, so invisible or reasoning items owned by an already finished turn cannot newly become non-active in the middle of that turn. The retention verdict itself is frozen once before prompt construction (`turn.rs:374`), not again in the sampling retry loop.

## Normalization

`normalize_history` at `core/src/context_manager/history.rs:619-633` runs four deterministic repair filters:

1. `ensure_call_outputs_present` at `core/src/context_manager/normalize.rs:21-138`. If a function, local-shell, tool-search, or custom-tool call has no matching output, a synthetic `aborted` output is inserted immediately after the call. The callsites that test for missing outputs are at `normalize.rs:52-134`.
2. `remove_orphan_outputs` at `normalize.rs:155-225`. A function or custom output is removed if its call ID is absent (`normalize.rs:184-202`). A client tool-search output is removed if its call ID is absent; server-executed tool-search outputs are left alone (`normalize.rs:203-213`).
3. `strip_images_when_unsupported` at `normalize.rs:328-377`. Its top-level gate is `!input_modalities.contains(&InputModality::Image)` (`normalize.rs:334-337`). Messages, tool outputs, and image-generation results are then replaced or cleared as applicable.
4. `strip_audio_when_unsupported` at `normalize.rs:381-420`. Its top-level gate is `!input_modalities.contains(&InputModality::Audio)` (`normalize.rs:384-386`).

These are idempotent prompt-copy repairs, not turn-scoped retention decisions. They can run on every prompt construction, including a sampling retry in the middle of a turn. In practice, missing-output and orphan-output repair fires only if that condition exists in stored history; unsupported media stripping fires deterministically whenever the selected model lacks the modality and relevant content is present.

Normalization does not create or consume `prefix_break`. Its changes are independent of the cache-break accounting in `ContextFilterReport`.

## Tool-output shrinker

`shrink_completed_outputs` is implemented at `core/src/context_manager/tool_output.rs:130-183`. For each envelope it requires all of the following:

1. The output belongs to a completed turn. The closure supplied by `for_prompt_annotated` computes this as `!belongs_to_active_turn(active_turn_id, metadata.tool_output_turn)` (`history.rs:324-329`). `tool_output_turn` is assigned only to function-call outputs when recorded (`core/src/session/mod.rs:3244-3247`).
2. The item is a `FunctionCallOutput` (`tool_output.rs:146-152`).
3. The output was successful: `output.success == Some(true)` (`tool_output.rs:154-156`).
4. Its call ID is paired with an allowlisted command. The pairing and allowlist lookup are at `tool_output.rs:134-159` and `tool_output.rs:186-270`; the command parser refuses chained/redirected shell lines at `tool_output.rs:238-248`.
5. The output body is `FunctionCallOutputBody::Text` (`tool_output.rs:160-164`).
6. The text has at least `MIN_LINES_TO_SHRINK` lines. That constant is `5 + 30 + 10 = 45` at `tool_output.rs:26`; `shrink_text` returns `None` below it at `tool_output.rs:286-290`.
7. The envelope index is at or after `prefix_break`:

```rust
if !prefix_break.is_some_and(|prefix_break| index >= prefix_break) {
    report.shrinkable_before_break += 1;
    continue;
}
```

That gate is at `tool_output.rs:166-169`. The shrinker never creates a prefix break; it only rides on one already created by a dropped item. This is documented at `tool_output.rs:123-128`.

Because the output must be from a completed turn and must sit after a newly created prefix break, the shrinker is a turn-boundary mechanism in real operation. During an active turn, current outputs are excluded by the turn check, and retries keep the same active turn ID, so no new boundary is created. A prior-turn output can shrink only when the next turn's drop pass creates a break at or before that output.

## Why the shrinker does not fire in real sessions

The decisive blocked value is `prefix_break: None`, and the specific metadata value that normally prevents it is `reasoning_retained: Some(true)`.

The chain is:

1. `ReasoningCostModel` is enabled by default: `features/src/lib.rs:1089-1094`. Therefore `Session::freeze_reasoning_retention` does run (`core/src/session/mod.rs:4072-4098`).
2. At the next turn, `run_turn` calls it before the first prompt is built (`turn.rs:374`).
3. The retention optimizer starts at the latest possible break: `forced_break` is the first item that is dropped regardless, or `items.len()` if there is none (`core/src/reasoning_retention.rs:90-93`). It then initializes `best_break = forced_break` (`reasoning_retention.rs:131-132`).
4. The optimizer only moves `best_break` earlier if the cost of dropping reasoning and re-prefilling the suffix is lower than retaining it (`reasoning_retention.rs:134-145`). In ordinary finished turns, it decides not to break.
5. It stamps every undecided candidate with `index < best_break` (`reasoning_retention.rs:147-148`). When `best_break` is `items.len()`, every such candidate is stamped `true`.
6. `stamp` writes `metadata.reasoning_retained = Some(retained)` (`reasoning_retention.rs:152-154`). So the blocking metadata value is `reasoning_retained: Some(true)`.
7. On the following prompt, `dropped_reason` preserves any reasoning whose verdict is `Some(true)` (`history.rs:731-738`). No item is dropped, so `report.prefix_break` remains `None`.
8. The shrinker's final gate then rejects every otherwise eligible output because `prefix_break.is_some_and(...)` is false (`tool_output.rs:166-169`).

The existing test `retained_reasoning_keeps_the_prompt_byte_identical` directly models this case: it contains a successful, allowlisted `cargo build` output of more than 100 lines and a prior-turn reasoning item stamped `Some(true)`. The test asserts that the output remains unchanged (`core/src/context_manager/history_tests.rs:619-657`). A companion test with one reasoning item stamped `Some(false)` creates `prefix_break = Some(2)` and the same output then shrinks (`history_tests.rs:660-735`).

Thus the shrinker is not dead because of the command allowlist, success flag, or line-count threshold. It is intentionally blocked by prompt-cache preservation: ordinary prior-turn reasoning is retained, no turn-scoped item is dropped, and therefore no cache break exists from which the shrinker is allowed to rewrite history.

## Adjacent ingest-time truncation

Tool outputs are also truncated when they are recorded, not during `for_prompt_annotated`. `record_items_with_metadata` calls `truncate_function_output_payload` for function and custom outputs at `core/src/context_manager/history.rs:212-236`. It uses `fallback_token_limit_override` when present, otherwise the normal truncation policy multiplied by 1.2. This happens before the prompt is built, but it is not the request-time shrinker and has no `prefix_break` gate.
