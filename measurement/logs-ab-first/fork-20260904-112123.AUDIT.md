## 5. Risks

1. **Siparis durumu literal'leri bozuktur ve kurye akisi tikar.** `main.py:199`, `main.py:214` ve `schema.sql:60` UTF-8'de bozuk `hazÄ±rlanÄ±yor` degerini yazar; `panels.py:174` dogru `hazırlanıyor` bekler. API ile olusan siparis kurye atanamaz. Ayrica `main.py:109` `can_review` icin bozuk `onaylandÄ±` ararken `reviews.py:34` ve `panels.py:238,261` dogru `onaylandi/ır` degerini kullanir. Cozum: tum status degerleri icin tek Python sabiti ve SQLite CHECK kisiti tanimlanmali; mevcut veri migrate edilmeli.
2. **Siparis detayi kimligi dogrulamadan sizar.** `main.py:119-139` hicbir dependency almaz; id bilen herkes adres, telefon, not, toplam ve urunleri okur. Cozum: `get_current_user` eklenip customer/restoran/kurye ownership veya yetkisi dogrulanmali.
3. **SQLite yabanci anahtarlari varsayilan olarak kapalidir.** `db.py:11-14` `PRAGMA foreign_keys = ON` calistirmaz; sema coklu FK tanimlar (`schema.sql:10,23,29-30,36-37,46,55,62-63,71-72`). Bozuk iliski verisi fiziksel olarak eklenebilir. Cozum: `get_db()` icinde baglanti acildiktan hemen sonra pragma calistirilmali.
4. **Token'lar suresizdir ve logout veritabanindan sildigi token'i gecersiz kilabilir.** `accounts.py:50-56` `created_at` yazsa da `auth.py:10-15` sure kontrolu yapmaz; frontend logout yalnizca `localStorage` temizler (`AuthContext.tsx:56-59`). Cozum: token tablosuna `expires_at`/`revoked_at` eklenmeli, `_user_from_token()` suresi/iptali kontrol etmeli ve logout server endpoint'i token'i silmeli.
5. **Para hesaplari kayan nokta uzerindedir.** `schema.sql:6-7,18,49,59,74` alanlar `REAL`; toplam ve bakiye islemleri float kullanir (`main.py:166-183`, `accounts.py:114-118`). Para birimlerinde bikumulatif yuvarlama hatasi olusabilir. Cozum: SQLite/Python cent tabanli integer hesap veya `Decimal` + ozel serializer'a gecilmeli; DB alanlari buna gore migrate edilmeli.
6. **Baglanti yonetimi savunmasizdir.** `main.py:84-115` ve `panels.py:68-81` `with get_db()` bloklari bittikten sonra `conn.execute` cagirir. `sqlite3.Connection` context manager transaction'i yonetir, baglanti kapatmaz; referans GC'ye kadar acik kalabilir. Cozum: sorgular `with` blogunda bitirilmeli veya `get_db()` `contextmanager` ile baglantiyi `close()` edecek sekilde yazilmali.
7. **Restoran kaydi degerlerini yeterince sinirlamaz.** `accounts.py:20-22` negatif `delivery_fee`, negatif/sifir `min_order` ve sinirsiz `eta_minutes` kabul edebilir; `image_emoji` icin kontrol yok ve varsayilan deger bozuk kodlanmistir (`accounts.py:23`). Cozum: `Field(ge=...)`, ust sinirlar, emoji/uzunluk kontrolu ve temiz varsayilan eklenmeli.
8. **Kurye olusturma girislerini dogrulamaz.** `panels.py:13-16` sadece alan tanimlar; `create_courier()` (`panels.py:128-145`) e-posta formati, sifre uzunlugu veya isim uzunlugu kontrol etmez. UI tarafinda sifre en az 6 var (`RestaurantPanel.tsx:171`), ama backend bunu garantilemez. Cozum: `RegisterInput` ile ayni email/sifre/role dogrulamasi buraya da uygulanmali.
9. **Checkout ve backend fiyatlari/bakiyesi farkli kaynaklardan gelir.** Backend guncel restoran ucretini ve fiyatlarini hesaplar (`main.py:166-174`), ancak UI stored `deliveryFee` ve lokal toplami kullanir (`CartContext.tsx:35-38`, `Checkout.tsx:14,20`). Siparis sonrasi `refreshUser()` cagrilmaz (`Checkout.tsx:46-49`) ve API yanitinda yeni bakiye donmez (`main.py:214`). Cozum: checkout, restoran/menu verisini sunucudan tazelemeli; siparis yaniti kalan bakiyeyi dondurmeli ve `refreshUser()` cagrilmali.
10. **Panel aksiyonlarinda API hatalari yakalanmaz.** `RestaurantPanel.tsx:42-46`, `134-144`, `159-166`, `CourierPanel.tsx:20-23`, `CustomerPanel.tsx:33-36` ve `RestaurantDetail.tsx:101-110` `await` cagrilari try/catch icinde degil; 409/400/403 hatalari sessiz unhandled promise olur. Cozum: her aksiyon icin yukleniyor/hata durumu eklenmeli ve `request()` mesaji ekranda gosterilmeli.

## 6. Frontend

Web istemcisi Vite altinda React Router ile kurulur (`main.tsx:9-18`; rotalar `App.tsx:47-54`) ve tum HTTP islemleri `api.ts` uzerinden yapilir. `request()` `localStorage["sepet-auth"]` icindeki token'i okur ve `Authorization: Bearer ...` basligi ekler (`api.ts:3-12`); hata yanitinda `detail` mesajini cikarip hata firlatir (`api.ts:13-20`). Gelistirme ortaminda `/api` istekleri Vite proxy ile `http://127.0.0.1:8000` adresine gider (`vite.config.ts:6-10`).

Auth durumu `AuthProvider` tarafindan yonetilir: login/register sonrasinda token ve user localStorage'a yazilir (`AuthContext.tsx:41-54`), acilista `fetchMe()` ile dogrulanir (`AuthContext.tsx:29-39`), refresh `GET /api/auth/me` yapar (`AuthContext.tsx:61-66`). Sepet ayrica localStorage'da tutulur (`CartContext.tsx:31-33`); urun fiyat ve teslimat ucreti satir icinde saklanir (`CartContext.tsx:35-48`, `types.ts:78-82`).

API ile frontend arasindaki uyusmazliklar:

- Backend siparis olustururken bozuk durumu yazar (`main.py:199`), frontend etiketleri dogru durumlari bekler: `CustomerPanel.tsx:7-12`, `RestaurantPanel.tsx:10-15`. Bu deger etiket tablosunda bulunamaz; CourierPanel zaten dogrudan durumu basar (`CourierPanel.tsx:35`).
- `can_review` backend'de yanlis status literal'i nedeniyle gercek onayli sipariste bile false kalir (`main.py:107-111`); form ancak true ve yorum yoksa gorunur (`RestaurantDetail.tsx:101`).
- Checkout'taki toplam stored teslimat ucretiyle hesaplanir (`Checkout.tsx:14,20`), backend ise guncel `restaurant.delivery_fee` kullanir (`main.py:174`). Restoran verisi degistiyse kullanici farkli toplam gorebilir.
- Checkout bakiyeyi siparis sonrasi yenilemez (`Checkout.tsx:46-49`); backend de yanitta bakiye dondurmez (`main.py:214`). Header/checkout eski bakiyeyi gosterebilir.
- Sepet'teki menu fiyatlari ekleme aninda saklanir (`CartContext.tsx:35-48`); backend menuden guncel fiyat okur (`main.py:157-166`). UI ve DB fiyati ayrisebilir.
- `Order` tipi `address`, `phone`, `note` alanlarini her sipariste bekler (`types.ts:34-47`); `GET /api/orders/{order_id}` bunlari auth'siz dondurdugu icin akis calisir ama güvenlik riski olusur (`main.py:119-139`, `OrderPage.tsx:14-18`, `OrderPage.tsx:37-38`).
- Restoran/kurye panelleri hata durumunu gosterme altyapisina kismen sahiptir, ama mutasyon hatalari try/catch'sizdir; `RestaurantPanel.tsx:42-46`, `134-144`, `159-166`, `CourierPanel.tsx:20-23`, `CustomerPanel.tsx:33-36` buna ornektir.
- Kayit ekraninda musteri ve restoran hesabi var; kurye hesabi yalnizca restoran panelinden olusturulur (`Account.tsx:14-75`, `RestaurantPanel.tsx:156-173`). Bu bir uyusmazlik degil tasarim karari, ancak backend ayni dogrulama standardini kurye icin uygulamaz.
